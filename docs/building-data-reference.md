## 一、数据基线与口径

- **来源**：`content/original-3.0/data.json`（原始 SLK 单位/技能表）、`gameplay.json`（职业与建筑组织）、`presentation.json`（技能表现）、`functions.json`（JASS `Trig_LevelUp_*`）、`artifacts/profession-parity-audit.json`（逐建筑审计产物）。
- **口径**：以下全部是**原版地图提取的静态数据**，用于说明「原图怎么配置」，不等于新版运行时的逐帧等价验收结果。对齐状态与未对齐项另见 [六职业对齐差异清单（2026-11-20）](../artifacts/parity-gap-2026-11-20.csv)。
- **单位说明**：金币取原始 `goldcost`（本图 `lumbercost` 全为 0）；人口取 `fused`；建造时间取 `bldtm`（秒）；生命取 `HP`；伤害取 `dmgplus1`/`dice1` 等合成的显示区间；护甲本图统一为 `5(divine)`；射程随档位 700 / 800 / 1000。
- **技能列**只列职业主技能，已省略每座塔固定附带的三个通用按钮 `A01H 出售`、`Avul 无敌的`、`A00U 功勋值`。

## 二、整体结构

六职业结构**完全同构**：每职业 11 座可直接建造 = 4 座 1 档 + 4 座 2 档 + 2 座 3 档 + 1 座终极；每职业 40 个形态 = 30 个普通形态 + 3 个 LvMax + 6 个套装 + 1 个终极。

形态构成：`10 条链 × 3 形态 = 30`，加 `3 个 LvMax + 6 个套装 + 1 个终极 = 40`。LvMax 需先造出本职业终极建筑（目标形态 `Requires` 指向终极建筑）；套装形态由装备/套装触发，不可直接建造。

## 三、通用规则

### 1. 建造条件（`Requires`）

前置塔必须已拥有并升到 **Lv3 形态**；1 档基础塔无前置。野蛮人「马加爵」另有 `e007`「只能建造 1 个马加爵」的数量限制（表中记为「限 1 座」）。这是全图统一的塔链，六职业一致。

### 2. 手动升级（`Upgrade`）

**不是补差价**：按目标形态的**完整 `goldcost`** 收费，加上目标形态人口差额，耗时目标形态 `bldtm`，并重新校验目标形态的 `Requires`（`engine/equipment.js:85-99`）。每职业 9 条、全图 **54 条**；价格与目标形态造价 100% 一致（已校验）。

### 3. 功勋（经验）体系

- **获取**：每次由建筑击杀敌人（玩家 8—11 死亡事件），该建筑功勋 `+= 当前波次 + 2`（`Trig_LevelUp_Actions` 首行）。
- **触发**：条件为「功勋 ≥ 阈值」且「功勋 < 波次 + 阈值 + 2」，即**首次跨过阈值的那次击杀**才晋升，避免重复触发。
- **快速模式**（`udg_nokuaisumode = false`）取消阈值，每次击杀都可能成长/领悟；领悟类技能为随机触发 `GetRandomInt(1, udg_jinengsjlv) == 1`。
- 阈值与 `engine/progression.js:2-29` 一致：

| 阶段 | 触发形态 | 功勋阈值 | 结果 |
|---|---|---:|---|
| 1 | 1 档 Lv1 | 150 | 晋升 Lv2；套装初级技能 → 中级 |
| 2 | 1 档 Lv2、2 档 Lv1 | 250 | 晋升下一形态；随机领悟 Lv1 增益技能 |
| 3 | 套装初级形态 | 400 | 套装中级技能 → 高级 |
| 4 | 2 档 Lv2、3 档 Lv1 | 500 | 晋升下一形态；随机领悟 Lv2 增益技能 |
| 5 | 3 档 Lv2 | 800 | 晋升 Lv3；随机领悟 Lv3 增益技能 |
| 6 | 1 档 Lv3 六座指定塔 | 1000（魔剑士步兵、盗贼扒手为 800） | 领悟「牺牲」类终极技能 |
| 7 | 六职业终极建筑 | 5000 | 领悟「强化 / 夺命 / 利滚利」类技能 |
| 8 | 游侠后羿 `h043` | 10000 | 额外领悟「强弩(光环)」 |
| 特例 | 魔剑士喷火兵 `h073→h072→h071` | 250 / 400 | 按施法次数晋升，且被 `Trig_LevelUp_Conditions` 排除击杀成长 |

阈值集合：`{150, 250, 400, 500, 800, 1000, 5000, 10000}`。召唤物击杀向本体建筑返还功勋属于对原图的有意扩展，见 [建筑成长说明](building-progression.md)。

### 4. 技能等级

建筑技能由 `abilList` 给出自定义技能 ID，等级数取自 `abilityData[code].levels`。本图多数职业技能是**每个建筑阶段一个独立 ID**，所以 `levels` 常为 1；技能名里的 `(Lv1)/(Lv2)/(LvMax)` 表示它对应的建筑阶段，**不是技能自身层数**。原生复用技能（如重击 `AHbh`）可有多级；同一光环 ID 来自不同等级来源时引擎保留较高等级。套装技能按 `jinengT1/T2/T3` 与 `jinengS1/S2/S3` 在功勋 150 / 400 时替换升级，成长领悟的技能由 JASS `UnitAddAbilityBJ` 追加。

## 六、校验结论与已知限制

生成时已执行的一致性校验：

- 240 行 × 35 列，无错列；66 座可建造建筑**全部带技能**；所有 `Requires` 前置 ID 在全表中存在。
- 54 条手动升级的价格与目标形态 `goldcost` **0 处不一致**；阈值集合与 `engine/progression.js` 一致。
- 查询页经浏览器验证：全部 240 行 → 筛「野蛮人」40 行 → 搜「驯兽师」4 行，无 JS 报错。

已知限制（**不随本数据表改变**）：

- 本表是**静态配置口径**。攻击前摇/转身帧、引导打断边界、状态强弱覆盖、兽群随机轨迹、护甲与伤害矩阵适用范围、多重箭与疾病云雾字段语义、粒子/光照逐像素等，仍需原客户端实机对照。
- 截至记录时，工作区仍有一组**未提交的攻击时序改动**（`engine/unit-timing.js` 等），单元回归未全绿；六职业对齐的未决项见 [对齐差异清单](../artifacts/parity-gap-2026-11-20.csv)。该状态属代码层，与本表的原版数据无关。
- `docs/model-resource-audit.md` 的缺失资源清单早于当前 manifest，`docs/original-map-reference.md` 中「`war3mapmisc.txt` 未加载」的陈述已滞后于代码，使用时以代码为准。

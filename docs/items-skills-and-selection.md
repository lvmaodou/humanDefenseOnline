# 物品、技能显示与紧密建造核查

依据本地原图 `content/original-3.0/script.j`、单位/物品/技能表和已提取 MDX 动画数据。

## 装备购买

- 物品表包含 297 个通用及自定义物品；`sellable=1` 不能证明本地图有商店出售该物品。
- 唯一包含商品列表的单位定义是地精商店 `ngme`，但原图脚本没有放置或创建该单位，也没有动态添加商品的逻辑。实际地图不存在装备商店，图鉴不能提供直接购买入口。
- 本地图脚本涉及 19 个物品：18 个职业套装掉落物品，以及用于地图剧情的 `I000` 火焰之球。图鉴按实际来源展示这些物品。
- `ChooseRandomItemBJ(10)` 使用物品 `oldLevel`；`ChooseRandomItemEx(ITEM_TYPE_ANY,8)` 使用 `Level`。两者只取 `pickRandom=1` 的候选，均应覆盖原图套装；修正了重构版本把两者都按旧等级筛选的问题。
- 服务端仍检查真实商店及商品列表，不能用图鉴或直接发请求凭空购买套装。

## 建筑技能效果

发现并修正的显示问题：

1. 通用特效把 Warcraft Y 坐标直接当成 Three Z，显示位置与单位关于地图中线镜像；改为共享的南北方向。
2. 原图常用 `AddSpecialEffect...` 后立即 `DestroyEffect` 来播放一次特效；旧实现直接跳过或立即移除模型。现按 MDX 的死亡、出生或单次 Stand 动画播放后清理。
3. 原版特效实例没有每帧推进动画，含粒子的模型会停在空白首帧；现推进动画及粒子时间。
4. 单位模型索引使用 `u<id>`，特效却按数字查找，导致跟随及附着点失效；现统一查找并使用原生附着点与地形高度。
5. 旧实现没有播放技能表中的 `Missileart`，因此冲击波、巨浪等原图技能弹道丢失；现使用其原始模型、速度与射程，并接收普通弹道的服务端更新。
6. 补齐异步加载后的释放、一次动画结束后的清理，避免残留空节点与模型。

原图触发器继续负责伤害、概率、自动施法和技能效果；建筑面板额外展示被动技能及原始说明，自动技能保留原始开关。

## 相邻格点击

模型包围盒包含攻击、死亡等动画范围，例如弓箭手模型的最大高度达到 879 码。旧实现先选中整个包围盒，误吞了相邻地面点击。

现在建造模式优先处理地面放置；普通选择建筑时将地面点对齐到原有 64 码网格，仅在该位置会与建筑 128×128 占地重叠时接受模型点击，兼顾身体部位的选中和相邻可建格的点击。选中农民时的地面移动操作保持独立。浏览器测试实际摆放三个中心间隔 128 码的建筑，验证占地相接时仍能继续选择地面并建造。

## 验证

- `npm test`：52 项通过，包括全部六职业、66 种职业建筑的攻击回归，以及套装来源、弹道、特效生命周期和相邻选择检查。
- `npm run test:browser -- desktop dense`：通过；实际建成三个占地相接的建筑，保留建筑信息面板和原图技能操作。
- `npm run test:browser -- mobile portrait placement`：通过；Chrome 模拟手机横竖屏触摸操作、面板滚动及单次建造。
- `npm run test:browser -- skills`：通过；使用原图 JASS 触发器生成技能事件，在真实 WebGL 渲染中检查雷霆一击、冲击波、巨浪的原始模型及动画帧推进。

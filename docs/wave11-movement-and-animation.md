# 魔剑士第 11 波移动与攻击停顿

第 11 波是原图的石像鬼 `ugar`，为飞行单位，基础移速 350。魔剑士三件套的 `A0EF` 光环在 1200 码内使敌军移速降低 25%，对应 262.5；这个效果本身不会使怪物完全停住，也不会暂停建筑攻击。

本次没有取得玩家当时的建筑组合与位置，使用步兵、刀狼骑士、机枪兵、圣堂武士、将军、刀圣的组合复现，另以无控制技能的场景排除正常减速、定身。

## 查到的问题

1. 原图会在同一个出怪点连续创建单位。碰撞代码拒绝任何仍然重叠的下一步，导致已经重叠的单位连走出重叠区也被拒绝。两个不带任何状态效果的石像鬼或地面怪即可复现完全不动。
2. 被其他单位临时挡住时，旧逻辑每半秒重新搜索相同地形路径；没有寻路网格时还会直接取消移动命令。动态拥堵无法靠重复搜索静态地形解除，怪物可能停止或持续增加计算量。
3. 移动到最终路点会同步执行进区域触发器；触发器刚下发下一段路径后，旧移动过程可能将新的命令清空。修复后只允许当前路径的过程结束自己的命令。
4. 客户端把每帧经过时间最多记为 0.05 秒，低于 20 FPS 时会少算动画和插值时间，造成模型动作迟缓或位置追赶。现允许最多补进 0.25 秒，战斗结算仍由服务端时间驱动。
5. 网络快照此前只用基础移速和“是否有移动命令”表示行走。现在使用实际减速后的移速，受定身、眩晕或拥堵时停止行走动作，效果结束后继续执行原来的移动命令。

## 修复方式

- 已重叠单位可以朝减少重叠的方向移动；仍会阻止新的碰撞或加深原有重叠。
- 因动态单位等待时保留路径并继续尝试绕行；只有地形方向全部受阻才限制频率地重新寻路。直线可达路径直接返回，避免分配全地图 A* 工作数组。
- 路点处理检查当前移动命令是否仍是原命令，保护触发器新下发的路径及朝向。
- 实际移动计算和网络展示共用移速计算，保留既有减速、光环、定身和眩晕结算。

## 验证

`npm test` 的 90 项检查通过。新增覆盖同点出怪分离、拥堵解除后恢复、等待时不重复寻路、终点触发下一段路，以及怪物减速/定身期间建筑继续攻击。

`node tests/wave11-performance-smoke.mjs` 在独立随机端口运行真实服务端与 Chrome，将已选择魔剑士的测试房间设置为第 11 波场景。使用 12 座不同魔剑士建筑、72 个石像鬼和另一路 200 个地面单位；提高测试石像鬼生命，避免在测量前被全部击杀。这是受控压力场景，不代表玩家当时的具体对局。

本机一次验证记录：

| 指标 | 结果 |
| --- | --- |
| 场景单位总数 | 299 |
| 持续推进超过 200 码的石像鬼 | 72 / 72 |
| 约 5 秒内建筑攻击事件 | 91 |
| 服务端更新耗时 P95 / 最大值 | 12.03 / 15.62 毫秒 |
| 浏览器平均帧率 / P95 帧间隔 | 38 FPS / 50 毫秒 |
| 模型加载失败、脚本错误 | 0 |

结果表明该场景中移动、攻击和状态更新继续运行；帧率仍取决于设备与画面负载。记录见 [数据](../artifacts/wave11-performance.json)、[画面](../artifacts/wave11-performance.png)。
